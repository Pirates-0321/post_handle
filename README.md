# 163邮箱重点邮件助手 (post_handle)

一个 Chrome / Edge 浏览器扩展（Manifest V3）：监控 163 网页邮箱中**重点关注的发件人**，收到其**新邮件时弹出常驻桌面通知**（不自动消失，手动关闭）。

## 功能

- 📮 **新邮件提醒**：收到重点关注对象的新邮件时，弹出系统桌面通知（常驻，需手动关闭）；点击通知自动聚焦邮箱标签页
- 🔄 **列表自动刷新**：163 网页版自身按间隔轮询服务器，扩展每 60 秒（可调）自动触发列表"刷新"，把新邮件检测延迟压缩到 1 分钟内
- 📇 **名单管理**：支持显示名、完整地址（`boss@company.com`）、整个域名（`@company.com`）三种规则，可增删、启停、加备注，通过浏览器账号跨设备同步
- 🧠 **地址学习**：悬停列表中的发件人，自动学习"显示名→地址"映射，让地址/域名规则生效
- ⚡ **一键关注**：点击工具栏图标，可直接把当前列表中的发件人加入名单
- 💾 **导入导出**：名单支持 JSON 备份与恢复

## 安装

1. 克隆本仓库：
   ```bash
   git clone https://github.com/Pirates-0321/post_handle.git
   ```
2. 打开浏览器扩展管理页（`chrome://extensions` 或 `edge://extensions`）
3. 开启右上角「**开发者模式**」
4. 点击「**加载已解压的扩展程序**」，选择本仓库目录
5. 打开 [163 邮箱](https://mail.163.com/) 并登录

## 使用

1. **添加关注**：点击工具栏扩展图标 → 在「当前页面发件人」中点「＋ 关注」；或进入「管理名单」手动添加
2. **接收提醒**：新邮件到达且发件人在名单内时，系统弹出常驻桌面通知，点击通知聚焦邮箱标签页，点 ✕ 手动关闭
3. **设置**：在名单管理页可开关桌面通知、调整列表自动刷新间隔

## 工作原理

```
mail.163.com 页面（React SPA，列表渲染在 #dvContainer）
  └─ content script：定位 div[sign="letter"] 邮件行
       ├─ 从 div[sign="start-from"] 取显示名、从 aria-label 取主题/时间
       ├─ 匹配重点名单
       ├─ 监听发件人 title 懒填充，学习"显示名→地址"映射
       ├─ 定时触发列表"刷新"按钮，压缩新邮件检测延迟
       └─ MutationObserver 识别新到达的未读重点邮件
            └─ 消息上报 → service worker → chrome.notifications 常驻桌面通知
名单与设置存 chrome.storage.sync（跨设备同步），学习映射存 chrome.storage.local
```

**关于匹配方式**：163 列表 DOM 中只有发件人**显示名**，没有邮箱地址（地址存在 JS 内存中）。因此名单支持三种规则：

| 规则类型 | 示例 | 生效时机 |
|---|---|---|
| 显示名 | `裴一发` | 立即可用（列表页直接匹配） |
| 完整地址 | `boss@company.com` | 扩展学习到该发件人地址后（悬停发件人即触发学习） |
| @域名 | `@company.com` | 同上 |

- 邮件行通过 163 的语义化属性 `sign="letter"` / `sign="start-from"` 定位，不依赖混淆类名
- 所有 DOM 选择器集中在 `src/content/selectors.js`，网易改版后只需调整该文件
- 通知按「显示名+主题+时间」去重，同一封邮件只提醒一次
- **首次打开页面只做基线扫描，不会对存量邮件批量提醒**

## 已知限制

- 需要浏览器保持 163 邮箱页面打开才会检测新邮件（扩展基于网页 DOM，不使用 IMAP）
- **安装或更新扩展后，必须手动刷新（F5）已打开的 163 邮箱标签页**，content script 才会注入
- 新邮件检测延迟取决于 163 列表的刷新节奏：扩展只能看到 DOM 中出现的邮件行。开启"列表自动刷新"（默认 60 秒）后延迟压缩到该间隔内；关闭则跟随 163 自身轮询节奏（可能数分钟）
- 显示名规则基于发件人自报的名字，理论上可被仿冒或重名；重要场景建议悬停发件人让扩展学习真实地址后改用地址规则
- 若网易改版导致 `sign` 属性失效，请调整 `src/content/selectors.js`
- 本扩展不收集、不上传任何邮箱数据，所有逻辑均在本地浏览器内完成

## 调试

扩展所有日志带 `[PH]` 前缀。排查步骤：

1. 在 `chrome://extensions` 重新加载扩展，然后**刷新邮箱页面**
2. 邮箱页面按 F12 →「控制台」，过滤框输入 `[PH]`
3. 正常应看到：`content script 已注入 frame: ...` → `扫描：识别邮件行 N 行` → `基线完成：命中重点邮件 X 行`
4. 悬停某个发件人后应看到 `学习到地址：名字 → xxx@yyy.com`
5. 若没有任何 `[PH]` 日志：扩展未注入，确认已刷新页面且扩展已启用
6. 若 `识别邮件行 0 行`：163 页面结构可能已改版，把控制台输出发给开发者适配

## 隐私与安全

- 不需要邮箱密码或授权码，仅作用于你已登录的网页界面
- 名单数据仅存于浏览器 `chrome.storage.sync`，不经过任何第三方服务器
- 仓库中不含任何凭据，可安全公开
